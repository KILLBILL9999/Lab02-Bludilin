# Лабораторная работа №2

## ПР2. Ответы на контрольные вопросы

1. **Почему для хранения денег используют decimal, а не double? Что может пойти не так с double?**
   Тип `double` хранит числа в двоичном формате с плавающей точкой. Некоторые десятичные дроби (например, 0.1) невозможно представить в двоичной системе абсолютно точно, из-за чего при арифметических операциях накапливается микроскопическая погрешность (например, 0.1 + 0.2 = 0.30000000000000004). В финансовых расчетах такая погрешность недопустима, так как может привести к потере копеек. `decimal` хранит числа в десятичном виде и обеспечивает точность без подобных ошибок округления.

2. **Что произойдёт, если целочисленный тип (например, byte) переполнится — то есть значение выйдет за границы диапазона?**
   Произойдет переполнение (overflow). Значение "обернется" по кругу и начнется с противоположной границы диапазона. Например, если прибавить 1 к максимальному значению `byte` (255), результат станет 0 (минимум диапазона).

3. **Чем var отличается от динамической типизации в Python? В какой момент компилятор определяет тип переменной, объявленной через var?**
   В Python тип переменной может меняться "на лету" во время выполнения программы (динамическая типизация). В C# `var` — это всего лишь синтаксический сахар. Тип определяется компилятором **один раз на этапе компиляции** на основе значения, присвоенного справа от знака `=`. После этого переменная имеет строго фиксированный тип, и присвоить ей значение другого типа нельзя.

4. **Какой тип данных всегда возвращает Console.ReadLine(), независимо от того, что ввёл пользователь?**
   Метод `Console.ReadLine()` всегда возвращает тип `string` (строку). Даже если пользователь ввел число, это будет строка, состоящая из символов-цифр.

5. **Чем int.Parse отличается от int.TryParse в поведении при некорректном вводе (например, буквы вместо цифр)?**
   При некорректном вводе `int.Parse` выбрасывает исключение `FormatException`, что приводит к аварийному завершению программы (если ошибка не обработана). `int.TryParse` не выбрасывает исключение, а возвращает логическое значение `false`, позволяя программе продолжить работу.

6. **Что означает false, возвращённый из int.TryParse, и что при этом попадёт в переменную, переданную через out?**
   `false` означает, что строку не удалось преобразовать в число (ввод был некорректным). В переменную, переданную через `out`, в этом случае попадет значение по умолчанию для данного типа (для `int` это `0`).

7. **Приведите пример, когда стоит использовать TryParse, а не Parse — и объясните, почему.**
   `TryParse` стоит использовать при вводе данных от пользователя (например, возраст, количество товаров, год рождения). Пользователь может случайно ввести букву или оставить поле пустым. Если использовать `Parse`, программа "упадет" с ошибкой. `TryParse` позволит нам проверить ввод и, например, вывести сообщение "Ошибка: введите число" и попросить ввести данные заново, не прерывая работу программы.
